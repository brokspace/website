What it does

Context, everywhere you work.

One local index of your code, shared by the terminal, the IDE, your LLM and every coding agent you use.

Search that reads code like you do

Functions, classes and doc sections are indexed whole, then found by meaning or by name: hybrid BM25 and semantic search over one repository, its submodules, or a folder full of them.

Shards: your workspace, programmable

Small programs in any language that react to workspace events on a local bus, each limited to the files, programs and network it declares up front. Start from the template, share them as git repositories.

Local-first

Nothing leaves your machine.
Unless you say so.

Brokspace runs next to your code. Your repositories are never sent anywhere to be indexed, and answers come from the model you point it at.

  • Indexed on your machine

    The index lives in .brokspace/, next to your code. No account, no upload, works offline.

  • The model you choose

    A local model by default. A hosted one only when you pick it, even for a single question.

  • Always up to date

    Saves, commits, pulls and branch switches reach the index within seconds.

CLI mode, IDE mode

One workspace. Two ways in.

Use brok in any terminal and editor, or open the same workspace in Brokspace IDE. Both read the same .brokspace/ folder, so you can switch at any time.

CLI

brok

Every feature, scriptable, with JSON output for your own tools.

brok search# find code by meaning or by name

brok ask# an answer, with sources

brok chat# follow-up questions

brok review# review your changes

brok commit# write the commit message

brok skill run# run a workflow

brok shard install# add an integration

Get started

Three commands to a workspace that answers back.

About fifteen minutes from zero, including a local model. Search works right away, even without one.

  1. 1

    Install brok

    $curl -fsSL https://brokspace.org/install.sh | sh

    Installs brok and brok-agent and verifies their checksums. Release notes

  2. 2

    Set up your workspace

    $cd ~/code/my-project && brok init

    Six guided steps: it picks a model that fits your machine, indexes your code and connects your coding agents. It asks before anything big.

  3. 3

    Ask away

    $brok ask "how does the refresh flow work?"

    Or brok search, brok chat, brok review. The index follows your edits from now on.
