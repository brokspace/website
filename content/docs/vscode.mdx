The Brokspace extension brings your local Brokspace workspace into VS Code.
It is built for VS Code and designed to run in editors based on it (see
[Other editors](#other-editors)). The extension
uses the `brok` CLI, so your terminal, coding agents and editor share the
same `.brokspace/` folder, index, LLM settings and memories.

## Install

Install the extension from the [VS Code Marketplace](https://marketplace.visualstudio.com/items?itemName=brokspace.brokspace) or run:

```sh
code --install-extension brokspace.brokspace
```

The extension needs the `brok` command line tool (0.4.0 or newer). If you
already have it, through [Homebrew, APT or the release binary](/docs/getting-started),
the extension finds it on your `PATH` or at `brokspace.brokPath` and uses it.

### Download on first use

If `brok` is not installed, the extension asks before doing anything. If you
agree, it:

- downloads the `brok` executable for your platform from the
  [brokspace/brok GitHub releases](https://github.com/brokspace/brok/releases)
  (about 150 to 220 MB, no other host);
- checks it against the SHA-256 published next to it, and installs nothing if
  it does not match;
- keeps it in the extension's own storage folder: no administrator rights and
  no change to your `PATH`.

A `brok` you already have always wins over the downloaded copy. Run
**Brokspace: Download and Install brok** to do it later; uninstalling the
extension removes the copy. The download is a convenience: if you manage tools
with a package manager, install `brok` that way and the extension will use it
(and will not update the downloaded copy). Downloading needs network access to
github.com once.

### Other editors

Visual Studio Code is the supported and tested editor. The extension uses only
the public VS Code extension API and declares VS Code 1.90 as its minimum, so it
is designed to install in editors that implement that API, such as Cursor,
Windsurf, Devin Desktop and VSCodium. That is a design goal, not a guarantee:

- **Not tested there.** We test in VS Code only. A fork may lag behind VS Code's API or lack parts of it
  (the `@brokspace` chat participant and the MCP registration depend on newer
  APIs and are skipped where they are missing). Features that need a missing API
  are turned off, and the rest keeps working.
- **Where to get it.** The Visual Studio Marketplace is for Microsoft's own
  products, so those editors do not install from it. Editors that use
  [Open VSX](https://open-vsx.org/extension/brokspace/brokspace) (Cursor, Windsurf,
  VSCodium and others) can install `brokspace.brokspace` from their extensions
  view. Otherwise download `brokspace-<version>.vsix` from the
  [GitHub releases](https://github.com/brokspace/vscode/releases) and use
  **Extensions: Install from VSIX**.
- **Report problems.** If something does not work in your editor, please
  [open an issue](https://github.com/brokspace/vscode/issues) with the editor and its version. We fix what we reasonably can.

The `brok` CLI, and with it MCP and skills for your coding agents, does not depend on any editor.

Open a project folder, then run **Brokspace: Set Up Workspace** from the
Brokspace sidebar or Command Palette. It creates `.brokspace/brok.yml`,
indexes the folder and starts Brokspace.

## The chat-first workspace

Clicking the Brokspace icon in the activity bar opens the chat. Settings and history are in the same sidebar, so you never leave it to configure or resume work.

![Searching a workspace by meaning in VS Code with Brokspace](https://raw.githubusercontent.com/brokspace/vscode/main/docs/images/search.gif)

- **Getting started.** A short checklist takes you from how your data is handled, through brok and the folder setup, to your first question. A model is optional; skip it and resume later. **Brokspace: Get Started** shows it again.
- **Chat.** Answers cite the code they come from. Type `/` for commands (`/review`, `/skill`, `/search`, `/remember`); Up and Down recall earlier prompts.
- **Context.** Attach the active file, the selection, your uncommitted changes, a folder, the open tabs, files you pick or the file's errors. They show as chips before you send, with what was done to them.
- **Activity.** Under each answer, the steps the assistant took and whether each only read, sent your question to your LLM, or changed something. Saving a memory asks first.
- **History.** Search, resume, rename and delete earlier chats of the workspace.
- **Settings.** The model, memory, linked workspaces, metrics and diagnostics, in a tab next to the chat.
- **Status bar.** With brok 0.13 or newer and extension 0.6.0, its tooltip shows whether keyword search, search by meaning, the agent and the model are ready, and offers one next step, such as rebuilding an index that cannot be read.

### The sidebar chat and `@brokspace` in Copilot Chat

Both use the same brok, index and memories. The sidebar chat is the full experience (context chips, history, activity, getting started) and works in any editor that runs the extension. `@brokspace` is the same agent as a participant of the editor's own chat, where that editor has the Chat API: a convenient way in when you already use Copilot Chat, without the Brokspace chat's own controls.

### What stays local and what is sent

- Local: the index, memories, chat history and search. The extension itself only touches the network for the optional brok download, after you agree.
- Sent to your model: when you ask, brok sends your question, the passages it retrieved, the recent turns of the conversation and the context you attached to the LLM you configured. With a local model (Ollama, LM Studio) that stays on your machine.
- Attached context never includes files that hold credentials or files Git ignores, secrets in text are masked, and sizes are bounded. With no LLM configured, nothing is sent.

## What you can do

- Search the workspace and linked workspaces by meaning or by name.
- Ask questions with source links, or chat without leaving the editor.
- Review your working tree or staged changes and write a commit message.
- Save, browse and search memories, including the selected code.
- Manage linked workspaces, skills and shards.
- Register Brokspace's MCP server for Copilot and other compatible clients.

The extension needs an LLM and the `brok-agent` shard for answers, reviews
and commit messages. Search works without an LLM.

## Useful commands

| Command | What it does |
|---|---|
| **Brokspace: Search** | Search code with `Ctrl+Alt+F` (`Cmd+Option+F` on macOS). |
| **Brokspace: Open Chat** | Ask a question with `Ctrl+Shift+Alt+B` (`Cmd+Shift+Option+B` on macOS). |
| **Brokspace: Set Up Workspace** | Create and index the Brokspace workspace. |
| **Brokspace: Doctor** | Check the executable, workspace and services. |
| **Brokspace: Report a Bug** | Open an issue with diagnostics, with secrets masked. |

For configuration and development details, see the
[extension repository](https://github.com/brokspace/vscode).
