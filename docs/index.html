Introduction

Brokspace makes any development workspace searchable and agent-ready, on your machine.

Brokspace (brok) indexes your code (one repository, its submodules, or a whole folder of repositories) into a local hybrid search engine, connects it to the LLM you choose, and plugs it into the coding agents you already use. Nothing leaves your machine unless you choose a hosted model.

Two ways to use it

CLI mode: brok

In any terminal and any editor. brok search, ask, chat, review, commit, skills and shards. Your coding agents get the brok_search tool through MCP.

IDE mode: Brokspace IDE

The same workspace in an IDE built around it: a home page that starts with your question, the Brokspace agent in the chat, search, reviews and commit messages one click away.

Both share the same .brokspace/ folder, so you can switch at any time.

What you get

  • Search that understands code. Functions, classes and sections are indexed whole, found by meaning or by name, across every repository.
  • Answers with sources. Ask your own LLM (Ollama, LM Studio, or a hosted model) about the workspace; every answer lists the code it used.
  • Reviews and commit messages from your staged or uncommitted changes.
  • Skills: 20 built-in workflows for AI (TDD, code review, specs...), and your own in a SKILL.md.
  • Shards: small programs that react to your workspace through a local, permissioned event bus.
