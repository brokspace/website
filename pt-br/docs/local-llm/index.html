Local LLM setup

Esta página ainda não foi traduzida; ela aparece em inglês.

Brokspace answers questions (brok ask) and runs skills (brok skill run) with any OpenAI-compatible model. Running it locally keeps everything free, private and offline. Search and indexing never need an LLM.

The short version

It:

  1. reads your RAM (and NVIDIA GPU memory) and picks a model size from the table below;
  2. looks for a running Ollama (localhost:11434) or LM Studio (localhost:1234) server;
  3. uses a model you already have, or offers to download the recommended one (ollama pull);
  4. writes the choice to .brokspace/brok.yml (llm.default).

Nothing installed yet? It prints the one-line install for your OS. Run it, then brok setup llm again. brok doctor tells you at any time whether the model is reachable.

What your machine can run

Sizes are for 4-bit quantized models (Q4_K_M), the best balance between speed and quality.

Model sizeMemory and GPUTypical hardwareRecommended (Ollama)

3B16 GB, no GPUBusiness laptops with integrated graphicsqwen2.5-coder:3b, llama3.2:3b
7B to 9B (sweet spot)16 GB with a GPU (6 GB+) or Apple Silicon; 32 GB without a GPUGaming laptops, M1/M2/M3 Macs, desktopsqwen2.5-coder:7b, llama3:8b, deepseek-r1:8b
14B to 32BA GPU with 12 GB+, or 32 GB with a GPU or Apple SiliconWorkstations, Mac Pro/Max with 32 GB+qwen2.5-coder:14b, deepseek-r1:32b

Without a GPU the model runs on the processor: memory decides what fits, but speed decides what is pleasant. A laptop CPU reads a long prompt into a 7B model at about 15 tokens per second, so a review takes 3 to 5 minutes; a 3B model is about twice as fast. That is why machines without a GPU get one size smaller. Only NVIDIA GPUs and Apple Silicon are detected; with another GPU that Ollama supports, pick the row for your GPU memory.

What to expect: 1B to 3B models answer questions about your code well enough (brok ask, brok chat), but they lose track of longer skills, so brok review, brok commit and most brok skill run workflows are much better with 7B or larger. Even at 7B, a review is a first pass that can be wrong; 14B and hosted models (brok review -p anthropic) review much better, and commit messages are already good at 7B.

brok setup llm applies exactly this table. Override it any time:

Option 2: LM Studio (graphical)

  1. Download it from lmstudio.ai (Windows .exe, macOS .dmg for Apple Silicon or Intel, Linux .AppImage: chmod +x LM_Studio-*.AppImage && ./LM_Studio-*.AppImage).
  2. Search for Qwen2.5-Coder-7B (or the size from the table), pick a Q4_K_M or Q5_K_M file and download it.
  3. Open the Developer / Local Server tab, load the model and press Start Server (it listens on http://localhost:1234).
  4. Run brok setup llm: it finds the server and lets you pick the model.

Keys are read from the environment, never stored in brok.yml, and secrets found in retrieved code are redacted before any prompt leaves your machine.

Using the same model elsewhere

  • Aider: aider --model ollama/qwen2.5-coder:7b inside your git repository (pip install aider-chat, Python 3.10 to 3.12).
  • Coding agents (Claude Code, Cursor, VS Code, Codex): brok setup agents gives them the Brokspace search tool and skills; see Integrations.

Performance tips

  • Apple Silicon: memory is unified, so a 16 GB Mac runs 7B/8B models fast.
  • NVIDIA / AMD GPUs: enable full GPU offload in LM Studio or Ollama.
  • Storage: keep models on an SSD; loading from a spinning disk is painfully slow.
  • Smaller is often better for interactive use: a fast 7B beats a slow 14B for everyday questions; switch per request with -p.
