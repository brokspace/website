Shards

Esta página ainda não foi traduzida; ela aparece em inglês.

Shards are small programs that react to workspace events. Each one is a separate process connected to the brok run event bus, restricted to the topics its manifest declares.

The fastest way to write one is the brok-shard-template repository; this page is the reference.

Lifecycle

To trigger your shard by hand, publish the event it listens to: brok bus emit file:changed '{"changed":["src/main.rs"],"deleted":[]}'. Windows PowerShell 5.1 drops the inner double quotes when it calls a program, so escape them there: '{\"changed\":[\"src/main.rs\"],\"deleted\":[]}' (PowerShell 7 and other shells need no escaping).

Installing:

  1. clones the repository (--depth 1, optional --tag) or uses the local directory;
  2. validates shard.json and the brok version requirement;
  3. shows the requested capabilities and asks for consent (--yes to skip in scripts);
  4. obtains the executable, in order of preference:
    • a release asset for this platform, verified against its SHA-256;
    • the manifest's build.command, run in the repository;
    • an entrypoint already present in the repository;
  5. moves it into .brokspace/shards/<name>/ and records the source, commit and binary hash in shards.lock.

Disable a shard without removing it in brok.yml:

shard.json

FieldRequiredRules
name✓^[a-z][a-z0-9-]{1,63}$, unique in the workspace

permissions.filesystem.read/writeWorkspace relative paths, no .., no absolute paths

permissions.envVariables to pass through: exact names, PREFIX_* or *_SUFFIX. BROK_* is reserved
subscribes_to / publishes_toTopic patterns; publishing to system:* (or *) is not allowed
build.commandProgram + arguments, executed without a shell
releases.<os>-<arch>https:// URL and 64 hex SHA-256; keys use Rust's std::env::consts names (linux-x86_64, macos-aarch64, windows-x86_64, …)

¹ A shard needs an entrypoint, skills, or both. Skill-only shards run no process, so they cannot declare topics, build or releases.

Unknown fields are rejected, and all violations are reported at once.

Topics

namespace:name, lowercase letters, digits, -, _ and . for sub-topics: file:changed, agent:ask.chunk. Patterns are exact topics or a prefix ending in * (agent:ask.*, file:*, *). Pick a namespace named after your shard for your own events. The well-known topics and their payloads are listed in Architecture.

Runtime contract

brok run starts the entrypoint with:

  • working directory = workspace root;
  • an environment containing only OS basics (PATH, HOME, TEMP, …), RUST_LOG, the variables allowed by permissions.env, and:
VariableValue
BROK_ENDPOINTSocket path / pipe name of the bus
BROK_TOKENThe shard's session token (secret)
BROK_SHARD_NAMEManifest name
BROK_WORKSPACEAbsolute workspace root
BROK_FS_READ / BROK_FS_WRITEDeclared paths, ;-separated
BROK_NETWORK1 or 0
  • stdout and stderr are captured line by line, prefixed with the shard name in the brok run output and appended to .brokspace/logs/<name>.log. Log to stderr.
  • On system:shutdown (delivered without subscribing), exit within 3 seconds.
  • A non-zero exit is a crash: the shard is restarted with backoff.

Using the SDK

  • Typed payloads implement brok_sdk::Payload (a serde type plus its topic).
  • client.request(event) returns a stream of replies; client.call::<Req, Res>(&req, timeout) waits for the first typed reply. Example: query the index with client.call::<SearchRequest, SearchResults>(…) (add index:search to publishes_to).
  • client.reply(&request, &payload) answers a request; only the requester receives it.
  • client.context() returns the workspace root, your shards.<name>.settings from brok.yml and the llm routing table.

Shards do not have to be written in Rust: anything that can open a Unix socket / named pipe and exchange length-prefixed JSON frames works. The frame format is documented in brok-sdk/src/frame.rs and codec.rs.

Security

What the runtime enforces: topic ACLs, source stamping, reply routing, the scrubbed environment, the working directory.

What is declared but not yet enforced by the OS: file system and network access. Consent at install time is the safeguard until OS sandboxes (Landlock, Seatbelt, AppContainer) land. build.command runs arbitrary code from the shard repository (e.g. build.rs) — the consent prompt shows it before it runs. Prefer shards that publish checksum-pinned releases.

Skills

A skill is a small, reusable workflow written for AI agents: a folder with a SKILL.md (YAML frontmatter name + description, then instructions) and optional reference files.
